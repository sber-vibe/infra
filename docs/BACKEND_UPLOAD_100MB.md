# Backend: загрузка файлов до 100 МБ

Frontend и nginx уже пропускают файл до **100 МБ**. Frontend проверяет размер до отправки, nginx принимает тело
запроса до 101 МБ. Сейчас backend отклоняет всё больше 50 МБ на файл и больше 50 МБ на все документы заявки,
поэтому файл от 50 до 100 МБ получит `413`, хотя интерфейс обещает 100 МБ.

## Что нужно от backend

| Правило | Значение |
|---|---|
| Максимальный размер одного файла в `POST /applications/{id}/documents` | 100 МБ (104 857 600 байт) |
| Максимальный размер multipart-запроса | 101 МБ: файл плюс поля формы |
| Суммарный размер документов одной заявки | не меньше 500 МБ, иначе второй крупный файл не загрузится. Точное значение выбирает backend |
| Превышение | `413` в формате Problem Details, `detail` по-русски, например «Файл больше 100 МБ» или «Превышен общий размер документов заявки (500 МБ)». Frontend покажет `detail` как есть |
| Пустой файл, неверный формат | без изменений: `400` / `415` |

Лимит на файл лучше задавать конфигурацией (переменная окружения), а не константой. Frontend берёт свой лимит из
`NEXT_PUBLIC_MAX_FILE_MB`, nginx — из `client_max_body_size`. Все три значения должны совпадать.

## На что обратить внимание

- **Память.** Файл на 100 МБ нельзя целиком держать в памяти по несколько копий одновременно: при параллельных
  загрузках JVM упадёт с OutOfMemory. Нужно хранить файл на диске или в хранилище и читать потоком.
  Сейчас контейнер получает `-XX:MaxRAMPercentage=75`. Если файлы остаются в памяти, контейнеру нужен лимит памяти с запасом.
- **Ответ сразу.** Приём файла подтверждается сразу (`201`, статус `UPLOADED`), а разбор идёт в фоне. Загрузка 100 МБ
  не должна ждать окончания анализа: nginx ждёт ответа до 120 с.
- **Анализ моделью.** Модели не нужен весь файл на 100 МБ. Как и сейчас, анализируются первые страницы и до 6000
  символов текста. Если файл слишком большой для разбора, документ получает `processingStatus: "FAILED"` и понятную
  `processingError` («Файл слишком большой для автоматического разбора, проверьте вручную»). Загрузка при этом не отклоняется,
  оригинал остаётся доступен специалисту.
- **Прямой AI API** `POST /api/v1/ai/analyze` может оставаться с лимитом 10 МБ: это отдельный маршрут для интеграции,
  frontend его не вызывает.
- **Предпросмотр** (`GET …/preview`) для DOCX/XLSX на 100 МБ может готовиться долго. Отвечать `202` с `Retry-After`,
  пока версия не готова, frontend подождёт.

## Как проверить

- Файл 99 МБ PDF → `201`, документ виден в заявке, оригинал скачивается целиком (размер совпадает).
- Файл 101 МБ → `413` с `detail` о лимите (от backend или от nginx).
- Две загрузки по 90 МБ одновременно → обе `201`, backend не падает.
- После перезапуска backend загруженный файл на месте.
