# Backend: сессия и продление токена

Начиная со следующего коммита frontend не теряет сессию при обновлении страницы и продлевает её сам.
Для этого frontend получает от Keycloak refresh token и за минуту до истечения access token обменивает его на новый.
Код backend для этого менять не нужно. Ниже правила, на которые frontend рассчитывает.

## Что делает frontend

- Токены лежат в `sessionStorage` вкладки. После обновления страницы сессия восстанавливается.
  Если access token уже истёк, frontend сначала продлевает его и только потом отправляет запросы.
- Каждый запрос к `/api/v1` идёт с заголовком `Authorization: Bearer <access token>`. Запросов без токена после входа нет.
- Продление выполняется через `POST {issuer}/protocol/openid-connect/token` с `grant_type=refresh_token` напрямую в Keycloak, backend в этом не участвует.
- Если продлить нельзя (сессия Keycloak закончилась или отозвана), frontend отправляет пользователя на вход
  с сообщением «Сессия истекла».
- Ответ `401` на актуальный токен завершает сессию. `401` на уже заменённый токен ни на что не влияет.

## Правила для backend

| Правило | Зачем |
|---|---|
| Принимать любой действующий access token этого realm и клиента, в том числе выпущенный при продлении | после продления меняется токен, а не пользователь |
| Не хранить серверную сессию и не привязываться к конкретному значению токена | токен меняется примерно раз в 15 минут |
| `401` отдавать только при отсутствующем, просроченном или неверном токене | frontend завершает сессию на любой `401` с актуальным токеном |
| Нет нужной роли — `403`, а не `401` | на `403` frontend сессию не завершает |
| Небольшой допуск по времени при проверке `exp`/`nbf` (до 30 с) | токен продлевается за минуту до истечения, расхождение часов не должно давать `401` |
| `401`/`403` в формате Problem Details | frontend показывает `detail` |

## Настройки Keycloak (infra, `realm-subsidy.json`)

- `accessTokenLifespan: 900`: access token живёт 15 минут, продлевается автоматически.
- `ssoSessionIdleTimeout: 1800`: если пользователь бездействует 30 минут, refresh token перестаёт работать и нужен повторный вход.
- `ssoSessionMaxLifespan: 36000`: максимальная длительность сессии 10 часов.
- Клиент `subsidy-frontend` должен выдавать refresh token. У публичного клиента это включено по умолчанию.

## Как проверить

- Войти, обновить страницу: пользователь остаётся в системе, в логе backend нет `401`.
- Подождать больше 15 минут, работая со страницей, затем обновить её: вход сохраняется,
  в логе Keycloak есть событие `REFRESH_TOKEN`.
- Не трогать вкладку больше 30 минут: при следующем действии появляется вход с сообщением «Сессия истекла».
