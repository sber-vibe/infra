# Локальный стенд и AI: настройка, обновление и проверка

## Версии и устройство

`backend/` и `frontend/` — Git-подмодули, закреплённые в коммите infra. Запуск Compose собирает именно их исходники; соседние папки `../Backend` и `../Frontend` не используются. AI-изменения из `Backend/feat/ai-document-analysis` до `a507cf8` объединены с main с сохранением API заявок, JWT, хранения H2 и Office-просмотра.

В обновлённом AI улучшены классификация, извлечение по фрагментам, восстановление некорректного ответа модели и признаки ручной проверки. Банковская выписка возвращает `fields.accounts` со списком счетов и `fields.passport_details`. Адаптер заявок сохраняет эти структуры как JSON-текст реквизитов. Если счёт один, его остаток переносится в `balance`; несколько остатков не суммируются автоматически, `balance` остаётся неопределённым.

## Вариант 1: готовый API анализа на другом ПК

В локальном `infra/.env` задайте:

```dotenv
HTTP_PORT=8088
SUBSIDY_PUBLIC_URL=http://localhost:8088
NEXT_PUBLIC_OIDC_ISSUER=http://localhost:8088/kc/realms/subsidy
NEXT_PUBLIC_OIDC_CLIENT_ID=subsidy-frontend
AI_REMOTE_URL=http://<адрес сервера>:8080/api/v1/ai/analyze
AI_REMOTE_API_KEY=<ключ удалённого сервиса>
```

Ключ берите из выданных параметров подключения, не коммитьте `.env` или файл с ключом. При непустом `AI_REMOTE_URL` оригиналы документов из заявок отправляются сервером на указанный адрес: multipart-поле `file`, заголовок `X-Api-Key`. Браузер ключ не получает. На один backend одновременно выполняется один удалённый анализ; ожидание ответа ограничено 180 секундами, задача обработки документа — 240 секундами.

Удалённый сервер обновляется отдельно его владельцем. Обновление локального подмодуля не заменяет код на другом ПК. Health удалённого сервера подтверждает доступность процесса; рабочую модель подтверждает запрос на анализ.

## Вариант 2: напрямую Ollama

Оставьте `AI_REMOTE_URL` пустым. В `.env` укажите `OLLAMA_URL=http://<адрес ПК с Ollama>:11434`, `OLLAMA_MODEL=qwen3-vl:4b-instruct`. Для Ollama на хосте Docker используйте `http://host.docker.internal:11434`. Модель устанавливается на ПК с Ollama командой `ollama pull qwen3-vl:4b-instruct`.

Прямой локальный `POST /api/v1/ai/analyze` использует Ollama независимо от `AI_REMOTE_URL`, требует локальный `AI_API_KEY` длиной от 32 символов и JWT специалиста. Ключ удалённого сервера `AI_REMOTE_API_KEY` и локальный `AI_API_KEY` имеют разные назначения.

## Обновление и запуск

Из каталога `infra`:

```powershell
git pull --ff-only
git submodule update --init --recursive
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Для изменения только подключения AI достаточно `docker compose up -d --build backend`. Изменения `NEXT_PUBLIC_*` требуют пересборки frontend. Файл `.env` не подставляется в Gradle/IDE автоматически — там переменные задаются в конфигурации запуска.

Не используйте `down -v` при обновлении: это удалит пользователей Keycloak и данные backend. H2 хранится в `backend-data:/app/data`, пользователи — в PostgreSQL volume Keycloak. Запускайте один backend на один файл H2.

## Вход и роли

Сайт: `http://localhost:8088`; админка сайта: `/admin`; консоль Keycloak: `/kc/admin`. Администратор master realm входит в консоль с параметрами `KEYCLOAK_ADMIN` и `KEYCLOAK_ADMIN_PASSWORD` из локального `.env`. Эти данные сами по себе не дают вход в админку сайта.

Каждый зарегистрированный пользователь получает `specialist` через `default-roles-subsidy`. Для админки сайта оператор назначает realm-роль `admin` выбранному пользователю в realm `subsidy`: Users → Role mapping → Assign role. После изменения ролей пользователь выходит и входит снова. Обе роли дают оба рабочих места; одна роль `admin` не даёт доступа к заявкам.

Импорт realm выполняется только при первом запуске и не обновляет существующий realm. Поэтому изменения default roles, SMTP и пользователей в действующем стенде применяются через консоль или Admin API отдельно от редактирования JSON. Удалённые пользователи автоматически не восстанавливаются при пересборке.

## Почта

Текущий infra содержит Mailpit; интерфейс ящика доступен на `/mail/`. Для существующего realm в Realm settings → Email задайте host `mailpit`, port `1025`, отключите SSL, StartTLS и Authentication, укажите адрес отправителя. Изменение JSON импорта или контейнерного окружения не меняет уже сохранённые SMTP-настройки realm. Для внешнего SMTP настройте реальные параметры отдельно.

## Лимиты и проверка

Frontend и nginx новой версии допускают 100 MiB на файл (nginx — 101 MiB на запрос), но текущий backend принимает 50 MiB на файл и ограничивает суммарное хранилище файлов процесса 50 MiB. Поэтому загрузки 50–100 MiB пока возвращают `413`. План согласования лимитов: [BACKEND_UPLOAD_100MB.md](BACKEND_UPLOAD_100MB.md). При прямом удалённом анализе действует также лимит удалённого сервера.

Проверяйте полный путь: войти специалистом, создать заявку, загрузить синтетический документ, дождаться `DONE`, проверить тип и реквизиты. Не отправляйте реальные персональные данные для проверки связи. При `FAILED` проверьте сеть и ключ, затем повторите обработку кнопкой сайта. Отсутствующая уверенность остаётся `null`; предупреждения AI не являются решением о выдаче субсидии.

Основные автоматические проверки backend: `AiBankAccountsTest`, `VisionAnalysisClientRecoveryTest`, `AiChunkAnalyzerTest`, `RemoteAiClientTest`, `ApplicationDocumentRecognizerTest`. Они используют тестовые ответы и не заменяют проверку реальной модели. `docker compose config --quiet` проверяет Compose без вывода секретов.
